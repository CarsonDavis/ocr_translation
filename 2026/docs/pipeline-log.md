**Column detection: what the spec asked for and what it took.** The recipe in the task sheet (1/2 scale, ink = luminance < 128, 25px moving average, dense = 15% of max, widest run = body) does not survive contact with these scans, and each departure below was forced by a measured failure:
1. *Backdrop and shadow are not ink.* The 1% outward margin leaves a rim of black backdrop, and the gutter shadow on the inner edge is dark for half its height. Either one sets the projection's max, and 15% of it lands above the printed text. Rows and columns darker than 60 over 35% of their length, or ink over 45% (columns) / 70% (rows) of it, are dropped first. Without this p080's body band came out 108px wide.
2. *Paper is not ink either.* On 450-year-old laid paper a luminance < 128 test reads about 3% "ink" in every blank column, and the gutter between the body and the margin column in this book is only about **25px** wide — narrower than the 25px-at-1/2-scale (= 50px) filter the sheet asks for. The two columns welded into one on every page. Fixed by a 3×3 cross erosion at **native** scale (which is why this runs at native scale, not 1/2: at 1/2 the same erosion eats the type) and a 25px filter in native pixels.
3. *The ink threshold is relative.* 128 is 62% of the CUDL scans' paper (about 205). The Gallica microfilm's paper sits near 130, where a fixed 128 makes a third of the leaf "ink". The threshold is now 62% of the page's own 75th-percentile luminance — 130 on the CUDL pages, 79 on p041.
4. *Pinholes.* A short line or a paragraph break can dip one column under the threshold and split a text block into three, after which "the widest run" takes a third of a page (p069). Runs closer than 8px are joined; the real gutter is never that narrow.
5. *Welds.* On 35 pages the gutter is bridged anyway and the body run spans more than 66% of the leaf. Such a run is cut at the quietest column in its outer third, provided that column is a real trough (< 60% of the run's median) and both halves stay ≥ 6% of the page. This is what recovers p041's and p143's margin columns.
6. *Sparse margins.* A page carrying one or two notes instead of a column of them (p008, p020, p029, p044) has no *dense* outer run: three lines of italic in a 4000px column are nowhere near 15% of the body's density. Every statistic tried — mean eroded ink, densest 120px cell — overlaps between a page with a two-line note (p029, 0.21%) and a page whose outer margin holds only a stain (p090, 0.216%). There is no honest test, so the band is taken **geometrically**: the whole outer margin from 120px inside the paper's edge to the body. 64 pages take this path. The cost is three largely blank strips on the dozen pages that really have nothing out there; the alternative was losing notes, which is a hole in the transcription. **`margin` is therefore null only for `p000-title`**, where `body` is the whole ink area by rule.

**Known limitation — the facing-page sliver.** The task sheet expects the "largest run wider than 40% of the frame" to exclude it. It does not: these openings were photographed with no dark gutter between the leaves, so paper runs unbroken from the frame edge across the facing leaf into the one being read, and the detected box keeps **130–350px of the facing page** on the inner edge (left on rectos, right on versos). Harmless for the reading strips — the sliver is always on the *inner* side, so it never competes for the margin band and is far too narrow to be the body — but it is visible in `pages/full`, `pages/read` and `foot.jpg`, and a reader should be told to ignore the strip of a different page at the gutter edge. Fixing it needs a leaf-edge detector (the edge shows only as a faint brightness step), which is not worth it before a reader has complained.

## Runbook (single-pass + arbitration)
Written 2026-09-26. Replaces the reconciler loop of Sept 21–22 (no model reconciler any more). Run everything from `2026/`. `wave.py` starts the helpers with `uv run --with pillow/jsonschema` itself when the interpreter lacks them.

1. **Render reads.** `uv run python scripts/wave.py next --size N` → for the next N pages without a final, renders a `read_single` prompt (`--model opus`, `--out-dir transcription/reads/{READER}`) for each missing reader into `$CORAS_SCRATCH` (default: this session's `scratchpad/waves/`), marks `status.readA/readB = dispatched`, prints `page reader prompt-path`. A page with one read on disk gets only the other reader. A reader already marked `dispatched` is skipped as in flight; `--redispatch` re-renders stale marks of agents that died. Context for each prompt: the three preceding pages' finals, or read A (then B) labelled "unreconciled read" where no final exists yet.
2. **Dispatch readers.** One Opus subagent per printed line, with exactly: "Your entire task is written in the prompt file `<path>`. Read it and follow it exactly, then return only the three-line summary it asks for." **Cap: 12 readers at a time**; backfill as they finish (ECONNRESET drops above ~12; resume the dropped agent rather than spawning a new one). Measured cost ≈ **$0.66 per read** (Opus 5.5, ~10 turns, ~15 image reads; `docs/checks/pilot-2026-09-24.md`), so ≈ $1.32 per page.
3. **Build queues.** `uv run python scripts/wave.py queue` → for every page with both reads, no final and no queue: `normalize_spacing` on both reads, `auto_resolve`, `diff_reads` (→ `transcription/diff/<id>.md`), `arbitrate_queue.py <id>` (→ `transcription/arbitration/queue/<id>.json` + `crops/<id>/`). Prints page, agreement, items. Idempotent; `--rebuild [PAGE…]` rebuilds existing queues (warns when decisions already exist, since item ids may shift).
4. **Carson arbitrates.** `uv run python scripts/arbitrate_server.py --port 8766` and open http://127.0.0.1:8766/ (use 127.0.0.1, not localhost). Decisions land in `transcription/arbitration/decisions/<id>.json`. `uv run python scripts/wave.py status` shows per page: reads (A/B on disk, a/b dispatched), queue, decided/total, final.
5. **Finalize.** `uv run python scripts/wave.py apply` → for every page without a final whose queue is fully decided (a 0-item queue counts as decided), runs `apply_arbitration.py <id>` into a temp file and moves it to `transcription/final/<id>.json` only if it exits 0 (validated); then syncs `status.final` in the manifest and re-runs `stitch_text.py` (→ `text/sections.json`) and prints where the stitched prefix stops. The prompt gives the whole `text/sections.json` as read-only context, the batch's section ids in order, and the previous batch's English; output is one `translation/sections/<id>.md` per section (each gated by `check_markers.py <id>`) and one report `translation/reports/batch-<first>--<last>.md`. 8. **Auto-defer and feed back (since 2026-10-03).** `uv run python scripts/wave.py defer` → `uv run python scripts/wave.py apply` → `uv run python scripts/render_translate.py --batch <id> --size 12 > $CORAS_SCRATCH/translate-<id>.md` → Fable translator (writes `translation/alt-choices/batch-<first>--<last>.json`) → `uv run python scripts/apply_translator_choices.py translation/alt-choices/batch-<first>--<last>.json` (→ `wave.py refinalize` runs automatically, re-stitching `text/sections.json` and `text/alts.json`).
